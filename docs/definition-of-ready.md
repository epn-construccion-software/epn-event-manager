# Definition of Ready

## Objetivo

La Definition of Ready establece las condiciones mínimas que debe cumplir
un ticket antes de comenzar su desarrollo.

Su propósito es evitar que el equipo inicie tareas ambiguas, incompletas
o sin criterios verificables.

## Criterios

Un ticket puede pasar de `Backlog` a `Ready` cuando cumple:

- [ ] Tiene un título claro y específico.
- [ ] Tiene una descripción completa.
- [ ] Está clasificado como Feature, Bug, Technical Debt o Task.
- [ ] Tiene criterios de aceptación verificables.
- [ ] Tiene prioridad definida.
- [ ] Tiene una estimación asignada.
- [ ] Tiene responsable.
- [ ] Sus dependencias están identificadas.
- [ ] Se conocen las pruebas necesarias.
- [ ] Se conoce la evidencia esperada.
- [ ] El equipo cuenta con información suficiente para iniciar el trabajo.

## Aplicación en Kanban

Los tickets que no cumplen estos criterios permanecen en `Backlog`.

Cuando todos los criterios están completos, el ticket puede pasar a `Ready`.
